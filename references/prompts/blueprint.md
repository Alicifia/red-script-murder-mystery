## 硬性要求
1. 蓝本合并大纲与机制，落到可写作粒度：已定方向、核心悬念、逐幕节拍（每幕必达事件与投放时机）、节奏控制（防冷场/控时预案）、机制执行细则；
2. **角色信息边界表（roleKnowledgeMap）是本环节核心交付**：为全部 {{playerCount}} 个角色逐行给出
   - knows：该角色可知信息（自身秘密、可知的关系与线索）；
   - hidden：该角色须隐瞒/不可得的信息（他人秘密、真相、未公开暗线）。
   边界表将作为质检「视角泄漏」检查的白名单：角色本只许出现 knows 范围的信息；hidden 中的内容一旦写进该角色本即判定泄漏。**任何角色的 knows 不得包含其 hidden 中的内容，角色间 knows 不得互相泄露对方 hidden**；
3. 蓝本正文最后一节固定为「## 角色信息边界表」，用文字复述上表要点（机读表以 JSON 字段为准）；
4. 只输出 JSON，结构如下（不要输出任何其他文字）：

```json
{
  "blueprintMd": "# 《剧本名》创作蓝本\n\n## 已定方向\n……\n## 角色信息边界表\n……",
  "roleKnowledgeMap": [
    { "role": "角色名（须与大纲角色设置一致）", "knows": "可知信息，分号分隔", "hidden": "须隐瞒信息，分号分隔" }
  ]
}
```
