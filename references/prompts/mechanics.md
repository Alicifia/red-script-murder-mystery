## 硬性要求
1. 按大纲拆解出 4-6 个机制环节，典型环节覆盖：开场/选角、搜证、讨论与投票、私聊与接头、任务与成就、终局裁决；
2. **每个环节必须给出 ≥2 种候选方案**，每种方案附：名称、一句话说明、利、弊（利/弊要具体，不得空泛）；
3. 机制设计须呼应大纲的幕结构与对抗线；跨幕资源（货币/积分/羁绊）须贯通；
4. 优先考虑 DM 可执行性：控时难度、物料成本、防卡死兜底；
5. 只输出 JSON，结构如下（不要输出任何其他文字）：

```json
{
  "slots": [
    {
      "id": "mech-search",
      "stage": "环节名称（如：搜证环节）",
      "goal": "该环节在大纲中的目标",
      "options": [
        { "id": "search-zone", "name": "方案名", "desc": "一句话说明", "pros": "利", "cons": "弊" }
      ]
    }
  ]
}
```
